# Domain Docs

This is a single-context repository. Read the root `GLOSSARY.md`, when present, for project terms, and relevant ADRs under `docs/adr/` before changing an area.

Use glossary terms in issue titles, specs, tests, and implementation notes. Surface any conflict with an ADR. The glossary and ADRs can be created when the project establishes terms or decisions; their absence does not block work.
